## 🚨 2. 即時修正すべきバグ・表示不備（High Priority）

### 2-1. お気に入りページが空白（本番で発生中・9/24 から）

* **問題点**: `/favorites.html` を開くと一覧も「NOTHING SAVED YET」も出ず、見出しとフッターだけ。
  - **対象ファイル/URL**: `LP/favorites.html:261` と `:391`
  - **発生状況**: スマホ・PC とも `TypeError: Cannot read properties of undefined (reading 'list')`。
    `favorites.js` に `defer` が付いているのに、インラインの `render()` が同期で `window.tjFav.list()` を呼ぶ。
    `defer` は 2026-09-24 の `dba4ffc4`（WP2: onclick 撤去）で付いた。以後 3 週間、本番で壊れている。
    GA4 の `favorite_add` が 28 日で 0 件なのはこれが一因。
  - **修正用コード案**（favorites.js は 4KB・data-hub.js と同様に同期で読む。`?v` は変えない）:
```html
<!-- LP/favorites.html:261  defer を外す -->
<script src="favorites.js?v=3"></script>
```
```js
// 代替（defer を残す場合）: LP/favorites.html:391
document.addEventListener('DOMContentLoaded', render);  // ← 直書きの render(); を置き換える
```
  - **確認**: 本番で `/favorites.html` を開き、コンソール例外 0・「NOTHING SAVED YET」表示・ハートで保存→一覧に出る、まで実ブラウザで見る。

### 2-2. TOP のスマホ LCP 画像が遅延読み込みになっている

* **問題点**: Lighthouse `lcp-lazy-loaded` 失敗。スマホでは 1 本目の記事写真（`.story-side-mobile-image`）が LCP だが `loading="lazy"` 固定。
  - **対象ファイル/URL**: `LP/index.html:973`（`storyMobileSrcset` の行）
  - **発生状況**: PC 用レール（`stories-visual`）の 1 枚目だけ eager にしてあり、スマホ用の同じ写真は常に lazy。
    10/11 の「二重読みしない」判断の副作用。LCP 3.3 秒の一因。
  - **修正用コード案**（描画は JS なので、幅で振り分ければ二重読みにならない）:
```js
// LP/index.html  featuredCol / sideCol の描画直前
const isNarrow = matchMedia('(max-width: 1100px)').matches;   // ← story-side-mobile-image が出る幅に合わせる
// レール（PC）: i === 0 && !isNarrow のときだけ eager + fetchpriority
loading="${i === 0 && !isNarrow ? 'eager' : 'lazy'}"${i === 0 && !isNarrow ? ' fetchpriority="high"' : ''}
// スマホ行: index === 0 && isNarrow のときだけ eager + fetchpriority
loading="${index === 0 && isNarrow ? 'eager' : 'lazy'}"${index === 0 && isNarrow ? ' fetchpriority="high"' : ''}
```
  - **確認**: 変更前後で `lighthouse --only-categories=performance` を同条件で 3 回ずつ。画像転送量が 10/11 の実測（390px dpr3 で 391KB）から増えないこと。

### 2-3. Google Fonts がレンダリングを 0.8 秒止めている（全ページ）

* **問題点**: `render-blocking-resources` 1,600〜1,670ms。内訳は fonts.googleapis.com の CSS 838ms、common.css / detail.css 各 158ms。
  - **対象ファイル/URL**: `LP/index.html:47`、`scripts/build-detail-pages.mjs`（`page()` の `<head>`）、ハブ 5 枚
  - **発生状況**: 3 書体（Bebas Neue / DM Sans 4 ウェイト / Space Mono）を外部 CSS 経由で読む。CSS を取りに行き、さらに woff2 を取りに行く 2 段の往復がモバイルで FCP 2.7〜2.9 秒を作っている。
  - **修正用コード案**: woff2 を `/fonts/` に置き、`common.css` で定義、LCP に効く 2 本だけ preload。
```html
<!-- <head>: googleapis の <link> と preconnect 2 行を削除し、代わりに -->
<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/dm-sans-400.woff2">
<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/bebas-neue-400.woff2">
```
```css
/* common.css 冒頭 */
@font-face { font-family: 'DM Sans'; font-weight: 200 500; font-display: swap;
  src: url('/fonts/dm-sans-var.woff2') format('woff2'); }
@font-face { font-family: 'Bebas Neue'; font-weight: 400; font-display: swap;
  src: url('/fonts/bebas-neue-400.woff2') format('woff2'); }
@font-face { font-family: 'Space Mono'; font-weight: 400; font-display: swap;
  src: url('/fonts/space-mono-400.woff2') format('woff2'); }
```
  - CSP の `style-src` / `font-src` から `fonts.googleapis.com` / `fonts.gstatic.com` を外せる（§9-44 の方針どおり外部依存が 1 つ減る）。
  - **期待値**: FCP −0.6〜0.8 秒、LCP 3.3 → 2.5 秒前後。`?v` を上げる（common.css）。

### 2-4. TOP のスマホ文字が小さすぎる（69% が 12px 未満）

* **問題点**: Lighthouse `font-size` 30.9% legible。10px のモノスペース字間広めは実機で読めない。
