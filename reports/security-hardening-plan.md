# Security / reliability hardening plan

更新日: 2026-08-06

## 実測した最優先課題

### 1. Publish が参照切れで停止し、本番が古いままになる

2026-08-05 の Publish pipeline `31023946153` は、`LINEUPS.ARTIST_ID=yazzus`
の参照切れで停止した。停止自体は壊れたリンクを公開しないため正しいが、
エラーが1件だけで復旧に必要な開催回が分からなかった。

今回、生成器が参照切れを全件収集し、アーティストIDと該当 EDITION_ID を一覧表示するよう改善した。

### 2. CMS認証の境界

- セッショントークンを `localStorage` に保存しているため、同一オリジンでXSSが成立すると窃取可能
- CMSは公開サイトと同一オリジンにある
- GAS側の認証・有効期限・権限分離は外部スクリプトであり、このリポジトリだけでは完全検証できない

短期: CSP、URL/HTML入力検証、トークンTTL、操作エラーの明示、監査ログ。
中期: CMSを別オリジンへ分離し、HttpOnly/SameSite Cookieへ移行。

### 3. バックアップ/Publishの信頼性

- Backup はGAS認証エラー時に保存を停止する設計になっている
- Publish は生成・検査・sitemap・Deployを一本化済みだが、入力参照切れ時は停止する
- 再実行時に同じデータを安全に再処理できること、失敗理由を復旧担当へ渡すことを強化する

## 実装優先順位

1. 参照切れの全件診断と復旧手順（今回着手）
2. CMS/GASの認証・権限・監査ログ・レート制限
3. URL、HTML、画像URL、アップロードの許可リストとサイズ上限
4. Publish/Backupの失敗通知、再実行、バックアップ完全性チェック
5. GitHub Actionsの権限最小化、依存アクション固定、secret scanning
6. 実ブラウザ回帰、モバイル表示、負荷/転送量の継続計測

## 変更しない原則

- 参照切れを黙って無リンク化して公開しない
- 認証をフロントエンドだけで「安全」と判断しない
- スプレッドシートの値を承認なしに推測修正しない
- 静的配信に不要な実行時バックエンドを追加しない
