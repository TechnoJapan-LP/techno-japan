# 記事本文のブロック追加設計: プルクオート / アーティストカード / 表 / 折りたたみ

作成: 2026-10-09 / 状態: **提案（未実装・ユーザー判断待ち）** / 実装: Codex（設計・検証は Claude）

## 0. いま使えるもの・使えないもの（2026-10-09 実測）

| ブロック | CMS で使えるか | 記事ページでの見た目 | 公開記事での使用数 |
|---|---|---|---|
| 引用（blockquote） | ◯ ツールバーに「引用」ボタンあり | 左に赤い縦線、斜体、少し薄い色（detail.css 61行） | 0 |
| **プルクオート**（本文から一文を抜き出して大きく見せる） | △ 上の「引用」で代用するしかない。専用の見た目は無い | — | 0 |
| **カード** | ◯ イベントカードだけ（`[[event\|…]]`、入力フォーム付きボタンあり） | 日程・名前・場所・LINEUP・写真（detail.css 68〜115行） | 69 |
| フェス／アーティスト／会場への参照 | ◯ `@` で名前検索 → `[[artist:dj-nobu]]` 等 | **文中のリンクになるだけ**（カードにはならない） | 0（自動リンクが名前を拾うため不要になっている） |
| **アーティストカード** | ✕ 無い | — | — |
| **表** | ✕ 無い。エディタ（Quill 1.3.7）に表機能が無く、記事側の CSS にも表の装飾が無い | — | 0 |
| **折りたたみ**（開閉できる補足） | ✕ 無い | — | 0 |

> 数え方: `LP/data.js` の記事本文を `<blockquote` `<table` `<details` `[[event` で検索。

## 1. 方針: 全部「ショートコード」で足す（イベントカードと同じ経路）

イベントカードは本文に `[[event|…]]` という短い記号を書き、公開時（`build-detail-pages.mjs`）に
静的な HTML へ変換している。新しいブロックも同じ経路に乗せる。

| 理由 | 中身 |
|---|---|
| エディタを壊さない | Quill はショートコードをただの文字として保存する。エディタの改造（表モジュール等）は要らない |
| 読者側に JS が要らない | 変換は公開時。記事ページは静的 HTML のまま。検索エンジンにも全文届く |
| CMS のプレビューで同じ絵が出る | `LP/article-shortcodes.js` は公開ビルドと CMS プレビューの両方が読む（1本の実装） |
| 既存の型がある | 入力フォーム（📦 イベントカード）、エラー表示（「ショートコードエラー」）、検査（preflight「記事イベントショートコード」）を流用できる |

**やらないこと**: Quill 2.x への更新（表モジュール目当て）。エディタ全体の挙動が変わり、
既存 312 箇所のフォント指定（`ql-font-*`）や画像レイアウトの再検証が要る。表1つのために払う代償が大きすぎる。

## 2. 各ブロックの設計

### 2-1. アーティストカード `[[artist-card:ID]]`（優先度 1）

```
[[artist-card:dj-nobu]]
[[artist-card:dj-nobu|この夜のクロージングを任された]]   ← 任意の一言
```

- **出どころはスプレッドシート ARTISTS（唯一のデータソース）**。カードに名前や経歴を手書きしない。
  公開時に ID から NAME / NAME_JA / GENRE / PREF・COUNTRY / IMAGE / BIO_JA・BIO_EN / INSTAGRAM・SOUNDCLOUD・BANDCAMP・WEBSITE を引く。
- 見た目（`.article-body .tj-artist-card`）: イベントカード（左の赤線＋上下の細い線）と同じ骨格。
  左に写真（正方形、`cardImagePath` の派生画像、`width/height` 付き = CLS を出さない）、右に
  ジャンル（mono 小文字）／名前（display）／拠点／経歴の冒頭 120 字（言語は記事の lang に従う: `localizedValue`）／
  「ARTIST PAGE →」リンク／SNS アイコン。スマホは写真を上に積む。
- 一言（2番目の項目）は、経歴の代わりに**記事側の文脈**を1行で添えるためのもの。あれば経歴より優先して出す。
- 構造化データ: `itemscope itemtype="https://schema.org/Person"`（ユニットは SCHEMA_TYPE に従い `MusicGroup`）。
- ID が ARTISTS に無い場合: 公開ビルドは**止める**（参照切れ。イベントカードのフェスID と同じ扱い。下書き記事は対象外）。
- CMS: 既存の `@` メニュー（名前検索）に「リンクで挿入」「カードで挿入」の2択を足す。プレビューは `ARTIST_DB` から描く。
- 自動リンク（本文中のアーティスト名を自動でリンクする仕組み）はカードの中では**働かせない**（カード内の名前が二重リンクになる）。

### 2-2. プルクオート `[[pullquote|本文|出典]]`（優先度 2）

```
[[pullquote|ふたつの顔、初のクロージング、そして10年ぶりの帰還。]]
[[pullquote|朝の光の中で鳴らす一音は、夜の百音より強い。|DJ Nobu]]
```

- 「引用」ボタン（blockquote）は**他人の言葉を引く**ため、プルクオートは**本文の一文を抜き出して見せる**ため。役割が違うので別物にする。既存 blockquote の見た目は変えない。
- 見た目（`.article-body .tj-pullquote`）: 本文幅いっぱい、display フォント（記事 h2 と同じ Bebas / 日本語は太字）、
  `clamp(22px, 3.2vw, 34px)`、上に赤い短い横線、下に出典（mono 小文字）。折り返しは記事見出しと同じ
  `word-break: keep-all; word-break: auto-phrase;`（§9-99）。
- 一記事に多用しない（スタイルガイドに「1記事 1〜2 本まで」を追記）。
- CMS: ツールバー横の既存「ブロック挿入」の並びに「❝ プルクオート」ボタン。選択中の文があればそれを初期値にする。

### 2-3. 折りたたみ `[[details|見出し]] … [[/details]]`（優先度 3）

```
[[details|セットリスト全曲]]
（ここに段落・リスト・画像。複数段落可）
[[/details]]
```

- HTML 標準の `<details><summary>` に変換する。**JS ゼロ**で開閉できる。閉じた中身も検索エンジンは読む。
- 用途: セットリスト、注意事項、長い補足、FAQ。本文の流れを止めずに置ける。
- 変換の注意: Quill は各行を `<p>` で包むので、`<p>[[details|…]]</p>` と `<p>[[/details]]</p>` を**段落ごと**取り除いて
  その間を `<details>` に入れる。閉じ忘れは「ショートコードエラー: [[/details]] がありません」としてプレビューで止め、公開ビルドも止める。
- 見た目: 上下に細い線、見出し行の左に「＋」（開くと「−」、CSS の `details[open]` だけで切替）。
- 入れ子は**禁止**（パーサを単純に保つ。必要になった例が出てから考える）。

### 2-4. 表 `[[table|…]]`（優先度 4・最後）

```
[[table|日程;会場;料金|12/28;Phu Quoc;$120|12/29;Beach Stage;$90]]
```

- 1行で書く（イベントカードと同じ流儀）。`|` が行、`;` がセル。1行目が見出し行。
- 変換: `<div class="tj-table-wrap"><table>…</table></div>`。外側は `overflow-x: auto`（AGENTS「表・図・コードだけは横に広くてよい、ただし自前の横スクロール枠に入れる」）。
- セル内で `;` `|` を使いたい場合は全角「；」「｜」で書く（そのまま表示される）。
- 列数が行ごとに違うときは、足りないセルを空にして揃える（止めない。表は内容が主役で、形の乱れは目で分かる）。
- CMS: 「表」ボタン → 行数・列数を選ぶ小さなグリッド入力。保存時にショートコード1行へ畳む。
- 最後にした理由: 使用実績 0、日程・会場・出演者は既にヒーローや FAQ やイベントカードで出ている。欲しくなった記事が出てから作っても遅くない。

## 3. 触るファイルと、守る規則

| ファイル | 変更 | 注意 |
|---|---|---|
| `LP/article-shortcodes.js` | パーサと描画の追加（4種） | 公開ビルドと CMS プレビューの共通部。`new Function` / `eval` 禁止（CSP） |
| `scripts/build-detail-pages.mjs` | `makeEntityResolver` に ARTISTS を渡す。アーティストカードの参照切れ検査 | 自動リンクをカード内で働かせない順序にする |
| `LP/detail.css` | 4ブロックの見た目。`DETAIL_CSS_VERSION` を上げる | 記事見出しと同じ折り返し指定（§9-99） |
| `LP/cms.js` / `LP/cms.css` / `LP/cms.html` | 挿入ボタン・入力フォーム・プレビュー | **Publish 経路の規則**: 触ったら `gh workflow run "Publish pipeline"` を自分で流し、CMS を `?cb=` 付きで開いて実行する |
| `scripts/check_article_shortcodes*`（preflight「記事イベントショートコード」） | 4種の変換の単体テストを追加 | 閉じ忘れ・参照切れ・エスケープ（`<` `&`）を必ず入れる |
| `docs/writing/Techno_Japan_Web_Style_Guide.md` | 使いどころ（プルクオートは 1〜2 本、折りたたみは補足のみ） | — |

## 4. 進め方（1フェーズ = Codex への1依頼）

1. アーティストカード（描画・ビルド・CSS・CMS の2択メニュー・テスト）→ 実記事1本で JA/EN・PC/スマホ確認 → Publish pipeline を流す
2. プルクオート
3. 折りたたみ
4. 表（必要になったら）

各フェーズの完了条件: preflight 全件成功、実ブラウザで入力→プレビュー→保存→再表示で値が消えないこと、
公開ページで JA/EN が同じ構造で出ること、`reports/handoff.md` に実測を記録。
