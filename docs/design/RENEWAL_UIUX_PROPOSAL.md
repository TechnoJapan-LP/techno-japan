# Techno Japan リニューアル UI/UX 仕様案（Codex 実装用）

作成: 2026-08-21 / 対象: techno-japan.media（`LP/` 配下の静的サイト）

この文書は「参考サイト5つの要素を、今の Techno Japan に **どこまで入れ、どこで止めるか**」を決めたものです。
Codex に渡すときは、§6 のフェーズを1つずつ切り出して指示してください。

## 非エンジニア向け要約

### このリニューアルで目指すこと

Techno Japanを「かっこいいサイト」にするだけではなく、次の3つを同時に実現します。

1. **探しやすくする** — フェス、アーティスト、会場を、今より少ない操作で見つけられる。
2. **読みたくなるようにする** — STORIESでは、雑誌を開いたときのような強い第一印象をつくる。
3. **迷わず行動できるようにする** — 日程を見る、詳細を読む、地図を開く、外部サイトへ行く、が明確になる。

参考サイトのような動きは、サイト全体に足すのではなく、**コンテンツの役割に合わせて場所を限定**します。データベースは静かで速く、Storiesだけが強く動く、という役割分担です。

### 変更前と変更後

| 場所 | 現在の課題 | リニューアル後 | 利用者に起きる変化 |
|---|---|---|---|
| STORIES | 記事が同じ強さで並ぶ | 最新記事を主役にした編集的な構成 | 読むべき記事がすぐ分かる |
| FESTIVALS | 画像カードを見ながら探す必要がある | 日付・地域・ジャンルを一行で比較 | 日程を短時間で比較できる |
| ARTISTS | 名前を探す操作が中心 | A-Z・検索・拠点を整理 | 知りたいアーティストへ直行できる |
| VENUES | 写真と場所情報が分かれている | 地図と会場一覧を連動 | 行きたい場所を決めやすい |
| 全体 | 表現を強くすると操作が重くなる | 動きは必要な箇所だけ | 世界観と使いやすさを両立できる |

### 実装の優先順位

優先順位は「見た目のインパクト」ではなく、利用頻度と改善効果で決めます。

| 優先度 | 先にやること | 先にやる理由 |
|---|---|---|
| **P0** | 検索・フィルタ・スマホ表示の土台を壊さない | 以降の変更で使いにくくしないため |
| **P1** | FESTIVALS の一覧整理 | 日常的に使われる検索機能で、効果が最も分かりやすい |
| **P1** | ARTISTS の A-Z・検索改善 | 件数が増えても探し方が変わらない |
| **P2** | STORIES のヒーローと記事グリッド | メディアとしての印象と回遊を強くする |
| **P2** | VENUES の地図連動 | 会場情報を行動につなげる |
| **P3** | ホバープレビューやページ遷移演出 | 機能が安定した後に世界観を加える |

P1まで終われば、利用者にとっての実用的な改善は完了です。P2以降は、使いやすさを損なわないことを確認しながら段階的に追加します。

### 成功したと判断する基準

- FESTIVALSで、スマホでも日付・名称・地域を同時に比較できる
- ARTISTSで、検索またはA-Zから目的の名前に到達できる
- VENUESで、一覧から地図・詳細・外部アクセス先へ迷わず移動できる
- STORIESの演出を無効にしても、記事を問題なく読める
- 画面表示が現在より明らかに遅くならない
- PC、スマホ、キーボード操作、動きを減らす設定のすべてで利用できる

「アニメーションが動いたか」ではなく、**目的の情報に早く到達できたか**を最終評価にします。

## 0. 先に結論（やる / やらない）

| | 判断 | 理由（今のサイトの事実） |
|---|---|---|
| 慣性スクロール（Locomotive / Lenis） | **やらない** | `#month-nav` のアンカー移動、`position: fixed` 8箇所、スマホの標準スクロール、reduced-motion を全部壊す。FESTIVALS の一覧探索を遅くするだけ |
| 画面全体の水平スクロール | **やらない** | データベース型メディアで一覧を横に流すと検索性が落ちる。**帯状の1エリアだけ**に限定（§2-1） |
| WebGL の画面遷移・歪み | **やらない** | すでに `@view-transition { navigation: auto }`（0.18s）が入っていて十分。WebGL は記事ページ 3.2MB 問題（AGENTS.md）に逆行 |
| カスタムカーソル（磁石追従） | **やらない** | 利用者の多数はタッチ端末。PC 限定で「画像プレビューの追従」だけ採用（§2-2） |
| ローディング演出 | **やらない** | 静的 HTML で 0.2 秒で出るものに幕を掛けるのは退化。代わりに遷移を「つなぐ」（§2-3） |
| キネティック・タイポグラフィ | **部分採用** | Bebas Neue が既にある。可変フォントを **見出し1本だけ** 追加し、幅軸（wdth）で動かす |
| グリッドの微破壊（オーバーラップ） | **STORIES のみ、1024px以上のみ** | スマホでは 1 カラムのまま。データベース3セクションではやらない |
| 引き算の美学（リスト化） | **FESTIVALS / ARTISTS に全面採用** | 現在のカード並びを「索引」に変える。これが今回いちばん効く変更 |

守る前提（AGENTS.md 由来）:
- SPA 詳細ビューは復活させない。ハブ→詳細は通常の `<a href>`。
- ハブ JS は JA/EN 同一、言語分岐は `tjLocalized`。`localize.js` に `defer` を付けない。
- CSP は `'self'` 中心。**新しい CDN は足さない**。ライブラリは `LP/vendor/` に置く。
- 変更前後のページ重量を `performance.getEntriesByType('resource')` で、dpr 2 で測って並べる。

## 1. セクション別の配置・UI 提案

### 1-1. STORIES（index / news / articles）— FACT × Glamcult

**トップ（index.html）のヒーロー = 「最新の1本」だけ**
- 画面いっぱいの 1 枚画像（既存の `image-derivatives.js` の srcset を使う、新規画像は増やさない）。
- 見出しは `clamp(2.75rem, 9vw, 10rem)`、本文 `1.0625rem`。この**約9倍のジャンプ率**が FACT の雑誌感の正体。装飾ではなく大きさで出す。
- 見出しフォントに **Archivo（可変: wdth 62–125 / wght 100–900）** を追加。Google Fonts から、`text=` で見出し文字だけ取る軽量ロードは不要（英数字主体なので通常ロードで 30KB 程度）。Bebas Neue は残し、ナビ・ラベルに降格。
- 初回表示で見出しの `font-stretch` を 62% → 100% へ 600ms で開く（CSS `@keyframes` のみ。`prefers-reduced-motion` で無効）。これが「キネティック」の全部。スクロール連動で文字を動かし続けることはしない。

**記事一覧（news.html）のグリッド微破壊**
- 12 カラム CSS Grid。1 本目は 8 カラム、2 本目は 4 カラムを **`margin-top: -3rem` でずらして重ねる**。3 本目以降は 4/4/4 の整列に戻す。「崩すのは最初の2本だけ」がルール。
- 1024px 未満は 1 カラム、重なり無し。スマホで重ねると画像とタイトルが干渉する。
- 既存の `tjApplyLazyBackgrounds` と `check_hub_pages.py` の data-bg 検査はそのまま通す。

**記事本文（articles/*.html）**
- 既存 `article-fx.js` v2 を土台にし、新規は2点だけ:
  1. 引用（`<blockquote>`）を `fx-bleed` の横幅いっぱいに出し、Archivo wdth 125 で組む。
  2. `h2` の直前に `<span class="chapter">` を生成し、`position: sticky` で章タイトルを上端に残す（読了バーと干渉しないよう top: 2px）。
- 本文幅は現状維持（65–70 文字）。

### 1-2. FESTIVALS — 180 Studios の「索引」

現在: カード（画像＋名前＋日程）の並び。→ **提案: 行（row）の索引**

```
2026.09.13–14   RURAL            長野 / 野外       Techno · Ambient     ▶
2026.09.20      LABYRINTH        新潟 / 苗場       Techno · Experimental
```

- 1 行 = `DATE`（Space Mono, tabular-nums）/ `NAME`（Archivo wdth 100, 1.5rem）/ 都道府県・会場 / ジャンル chip。画像は**出さない**（PC では §2-2 のホバープレビューで出す）。
- 月見出し（`#month-nav` と連動）を `position: sticky` の帯にし、**ここだけ横スクロール**（§2-1）。
- 既存の `#fest-filters` / `#fest-search` / `#mode-toggle`（地図）はそのまま。見た目だけ行索引に合わせる。
- 「開催中 / 今月 / 終了」を行の左端 2px のアクセント線で示す（色だけに頼らず、終了はテキストを `--text` 60% に）。
- スマホ: DATE を 1 行目、NAME を 2 行目に折る 2 行構成。1 画面に 8 件以上入ることを確認基準にする（現在のカードは 2–3 件）。

### 1-3. ARTISTS — A–Z と可変幅

- **A–Z レール**を左（PC）/ 上部 sticky（スマホ）に置く。押すとアンカー移動（`scroll-behavior: smooth` は既存）。
- 名前は Archivo、1 行 1 名、`font-size: clamp(1.5rem, 4vw, 3rem)`。右端に拠点都市を Space Mono で。
- ホバー時: `font-stretch` 100 → 118、200ms。**これが No Art の「追従」の代替**。カーソル演出無しで「触れた感」を出す。タッチ端末では `@media (hover: hover)` で無効。
- 既存の `search.js` の絞り込みはリストの行を `hidden` にするだけで成立。
- `bio` のガード無し展開で `undefined` が出た前歴（AGENTS.md）があるので、行には name / city / genre 以外を載せない。

### 1-4. VENUES — 地図と一体

- 22 件と少ないので索引化はしない。**地図を主、カードを従**にし、PC は左 40% 地図（sticky）/ 右 60% カード、スマホは地図を上部に折りたたみ（高さ 40vh、タップで展開）。
- カードホバーで Leaflet のマーカーを `setStyle` で赤点灯。逆にマーカークリックでカードへスクロール。
- 詳細ページ末尾の「近くの会場」帯だけ横スクロール（§2-1 と同じ部品）。

## 2. 機能性を損なわないインタラクション

### 2-1. 横スクロールは「帯」3箇所に限定
- FESTIVALS 月ナビ帯 / VENUES・FESTIVAL 詳細の「近く・関連」帯 / STORIES の「連載」帯。
- 実装は CSS のみ: `overflow-x: auto; scroll-snap-type: x mandatory; overscroll-behavior-x: contain;`。スクロールバーは非表示にせず細く（`scrollbar-width: thin`）。キーボードで ← → が効く。
- JS の水平ハイジャック（縦ホイールを横に変換）は**しない**。

### 2-2. ホバープレビュー（PC のみ、唯一の「追従」）
- FESTIVALS / ARTISTS の行にホバーすると、`position: fixed` の 240×160 画像がカーソルから 24px 右下に出る。位置は `requestAnimationFrame` で lerp 0.15 の遅れ追従。これが No Art の「磁石」感の最小単位。
- 画像は行の `data-thumb` から読む。**ホバー前に読まない**（`loading="lazy"` では無く、表示時に `src` を入れる）。ページ重量が増えないことを計測で示す。
- `@media (hover: none)` と `prefers-reduced-motion` では生成しない。

### 2-3. 遷移 = ローディングの代わりに「つなぐ」
- 既存の cross-document View Transitions を使い、行/カードの画像に `view-transition-name: hero-<id>` を付け、詳細ページのヒーロー画像と同名にする。一覧→詳細で画像がその場から広がる。
- 名前は build 時に `build-detail-pages.mjs` で埋める（id は既存の小文字ハイフン ID）。
- 非対応ブラウザは今までどおり 0.18s フェード。JS 不要。
- ローダー画面・プログレスリングは**追加しない**。

### 2-4. 押した手応え
- ボタン・chip は `:active { transform: scale(.97) }` 80ms。focus-visible は赤 2px アウトラインを全要素共通で。
- スクロール時のリビールは既存 article-fx の IntersectionObserver 方式を共通化し、ハブでは **使わない**（一覧は一瞬で全部見えるべき）。

## 3. 「本当に必要か」— 懸念と解決

| 提案 | 懸念 | 解決 |
|---|---|---|
| 可変フォント追加 | +30–60KB、FOUT で見出しが跳ねる | Archivo 1 ファイルのみ、`font-display: swap`、フォールバックを `Arial Narrow` 系にして幅差を抑える。CLS を Lighthouse で前後比較し、0.02 以内 |
| FESTIVALS の行索引 | 画像が無いと「雰囲気」が伝わらない | PC はホバープレビュー、スマホは行タップ→詳細で即ヒーロー。さらにトップに「今月のピックアップ 3 件」だけカードを残す |
| STORIES の重なり | スマホで破綻、CLS | 1024px 以上限定、重なりは `margin` で確定配置（絶対配置禁止）、画像は `image-dimensions.js` で width/height 既知 |
| ホバープレビューの追従 | 重さ・タッチ端末での誤動作 | hover: hover 限定、画像は表示時に取得、rAF 1 本。headless ではなく **実機スマホでタップ検証**（AGENTS.md の誤検知例に該当） |
| View Transitions の共有要素 | 同名が重複すると遷移しない | `view-transition-name` は画面に 1 つだけ。一覧側は `:hover` / `:focus-within` の行にのみ付与する |
| 横スクロール帯 | 縦スクロール中に横へ取られる | `overscroll-behavior-x: contain` と `scroll-snap`、帯の高さを 40vh 以下に |
| 章タイトル sticky | 読了バー・ナビと三重に重なる | top を `--safe-t + 2px`、ナビ非表示時のみ（既存のスクロールでナビを隠す挙動と連動） |
| すべて | 「実測した」の誤り | 変更前後を同じ方法で計測し `reports/handoff.md` に並べる。`bash scripts/preflight.sh` 通過が最低条件 |

## 4. 技術スタック（Codex への指定）

**追加しないもの**: GSAP / Locomotive Scroll / Lenis / Three.js / Framer Motion / React。
理由: CSP が `'self'`、静的 HTML、既存 JS 合計 50KB 台。ここに 100KB 級を足す価値が無い。

**使うもの（すべてブラウザ標準）**
| 目的 | 技術 | 備考 |
|---|---|---|
| 遷移 | View Transitions API（cross-document） | 既存。`view-transition-name` を追加するだけ |
| 見出しの動き | 可変フォント `font-stretch` / `font-variation-settings` + CSS `@keyframes` | Archivo を Google Fonts から（CSP 許可済みドメイン） |
| スクロール連動 | CSS Scroll-driven Animations（`animation-timeline: view()`）を `@supports` で。非対応は IntersectionObserver（既存 article-fx） | JS を増やさない |
| 横帯 | CSS `scroll-snap` | JS ゼロ |
| ホバープレビュー | `requestAnimationFrame` + lerp、素の JS 2KB | `LP/hover-preview.js`、`defer` 可 |
| 地図 | Leaflet 1.9.4（既存 vendor） | 変更なし |
| 画像 | 既存 `image-derivatives.js` srcset | `sizes` を実表示幅どおりに |
| 配色・字体 | 既存トークン `--bg #080808 / --text #f0ede8 / --accent #ff2d2d` | 新色は**足さない**。中間グレーは `color-mix(in oklch, var(--text) 60%, var(--bg))` で作る |

**予算**: JS 追加 ≤ 8KB gzip、フォント追加 ≤ 60KB、ハブの LCP 悪化なし（dpr 2、スマホ相当で計測）。

## 6. 実装フェーズ（非エンジニア向けの進め方）

各フェーズは、**目的を確認 → 小さく実装 → PC／スマホで確認 → 次へ進む**の順で進めます。前のフェーズが完了していない状態で、次の派手な演出を追加しません。

### P0 — 使いやすさの土台を固定する

**目的**: リニューアル中も、検索・リンク・スマホ操作を壊さない。

**やること**:

- 共通の文字サイズ、余白、フォーカス表示を整理
- 横スクロールする場所を限定し、操作できることを表示
- 動きを減らす設定でも同じ情報を読めるようにする
- 日本語版と英語版の表示件数・リンク数を確認

**利用者に起きる変化**: どのページでもボタンやリンクの見た目・押した感覚が統一され、スマホでも操作に迷いにくくなる。

**完了条件**: 既存ページの主要導線がすべて動き、PC 1280px／スマホ390px／キーボード操作で問題がない。

### P1 — FESTIVALSを「探すための一覧」にする

**目的**: フェスを画像の印象ではなく、日程・場所・ジャンルで比較できるようにする。

**やること**:

- カード中心の表示を、日付中心の行表示へ変更
- 月・地域・ジャンル・開催状態のフィルタを見つけやすくする
- 絞り込み条件をURLに保存し、リンクや戻る操作で状態を失わないようにする
- スマホでは「日付 → 名前 → 場所」の2〜3行に整理

**利用者に起きる変化**: 「9月の長野のテクノ系フェス」のような探し方が、一覧を何度も開き直さずにできる。

**完了条件**: スマホで1画面に少なくとも8件を確認でき、絞り込み・戻る・英語版でも同じ情報が保たれる。

### P1 — ARTISTSを名前から探せるようにする

**目的**: アーティスト数が増えても、目的の人物にすぐ到達できるようにする。

**やること**:

- A-Zインデックスを追加
- 検索欄をページ上部に固定
- 名前・拠点・ジャンルを同じ行で確認できるようにする
- PCだけ、行に触れたとき画像を小さくプレビューする

**利用者に起きる変化**: 名前を知っている場合は検索、知らない場合は拠点やジャンルから、どちらでも探せる。

**完了条件**: キーボード、タッチ、マウスのすべてで検索でき、ホバー演出がなくても情報が欠けない。

### P2 — STORIESでメディアらしさを強める

**目的**: 読むべき記事を明確にし、記事同士の回遊を増やす。

**やること**:

- 最新記事1本をヒーローとして強調
- 記事一覧の最初の2本だけグリッドを少し重ねる
- 記事本文の引用や章見出しに、限定的なタイポグラフィ演出を加える
- 関連するアーティスト・フェス・会場へ移動できる参照カードを整える

**利用者に起きる変化**: トップで読む記事を選びやすくなり、記事から関連する人物・場所・イベントへ自然に移動できる。

**完了条件**: 演出を無効にしても読書体験が成立し、画像やフォント追加によって表示速度とレイアウト安定性が悪化しない。

### P2 — VENUESを「行く場所を決める」画面にする

**目的**: 会場情報を、閲覧だけで終わらせず訪問につなげる。

**やること**:

- PCでは地図と一覧を連動
- スマホでは地図を折りたたみ、必要なときだけ開く
- 会場カード、住所、最寄り駅、SNS、外部地図への導線を統一
- マーカーと一覧の選択状態を同期

**利用者に起きる変化**: 「この会場はどこにあるか」「近くに他の会場があるか」を同じ画面で確認できる。

**完了条件**: 東京以外の会場も地図に表示され、一覧から地図、地図から詳細へ相互に移動できる。
