# TECHNO JAPAN 記事本文の書式仕様（記事提案 AI への入力用）

目的: 別プロジェクトの AI が、この仕様に従って記事（本文 HTML＋メタ情報）を出力すれば、CMS の「HTML」タブに貼るだけで公開できる。
人向けの説明は `ARTICLE_BODY_FEATURES.md`、文体のルールは `Techno_Japan_Web_Style_Guide.md`。この文書は**書式の正確さ**を優先する。

---

## 1. 納品の形（この3つを出す）

```
### META
ID: <小文字・数字・ハイフンのみ。対象+年+種別。例: transcendence-2026-report>
TITLE: <日本語タイトル>
TITLE_EN: <英語タイトル（任意）>
CATEGORY: <REPORT | COLUMN | INTERVIEW | NEWS | GUIDE | FESTIVAL&RAVE のどれか1つ>
DATE: <YYYY-MM-DD>
AUTHOR_ID: <例: techno-japan>
EXCERPT: <日本語の要約。全角 80〜120 字。検索結果の説明文に使われる（160 字で切れる）>
EXCERPT_EN: <英語の要約（任意）>
TAGS: <小文字の英単語をカンマ区切り。例: tokyo, clubs, guide>
festivalId: <関連フェスの ID（あれば1つ）>
artistIds: <アーティスト ID のカンマ区切り（任意）>
venueIds: <会場 ID のカンマ区切り（任意）>
IMAGE: <使う写真の指示を文章で。ファイルは人が CMS で入れる>

### BODY
<HTML（下の 2〜5 の規則に従う）>

### BODY_EN
<英語版 HTML（任意。無ければ省略）>
```

---

## 2. BODY に使ってよい HTML

| 要素 | 書き方 | 用途 |
|---|---|---|
| 段落 | `<p>…</p>` | 本文。1段落 2〜4 文。空行は `<p><br></p>` |
| 大見出し | `<h2>…</h2>` | 章。1記事に 3〜6 本。英字の固有名詞を含めてよい |
| 小見出し | `<h3>…</h3>` | 章の中の区切り |
| ラベル見出し | `<h4>…</h4>` | 「開催情報」など短い英字／ラベル |
| 強調 | `<strong>`、`<em>`、`<u>` | 使いすぎない |
| 外部リンク | `<a href="https://…" target="_blank" rel="noopener">テキスト</a>` | 公式サイト・チケットなど |
| 箇条書き | `<ul><li>…</li></ul>`、`<ol><li>…</li></ol>` | 開催情報、持ち物など |
| 引用 | `<blockquote>…</blockquote>` | **他人の言葉**を引くときだけ。インタビューの発言には使わない（`[[quote]]`）。自分の本文を抜き出すときは `[[pullquote]]`（§3） |
| 行内改行 | `<br>` | 住所・歌詞など、段落を分けたくないとき |

**使ってはいけないもの**: `<table>` `<details>`（折りたたみは §3-5 のショートコードで）`<iframe>` `<script>` `<style>` `style="…"` 属性、`<div>`、`<span>` の独自クラス、Markdown 記法（`**` `##` `- ` など）。
**画像**: `<img>` は書かない。写真を入れたい位置に `<p>[写真: 何を写した写真か・横長か縦長か]</p>` と書く。人が CMS で差し替える。

## 3. ブロック（ショートコード）

**共通ルール**
- 1つのショートコードは **1行・1段落**: `<p>[[…]]</p>`。前後に文を混ぜない。
- 値の中に `|` と `]` を書かない。必要なら全角 `｜` `］` にする。
- ID は小文字・数字・ハイフンのみ。**存在しない ID を書くと公開が止まる。** ID が分からないときはブロックにせず、文中に名前を書く（アーティスト名は自動でリンクされる）。

### 3-1. イベントカード
```
<p>[[event|名前|日程|場所|公式URL|出演者|補足|フェスID]]</p>
```
| 位置 | 項目 | 必須 | 書式 |
|---|---|---|---|
| 1 | 名前 | ◯ | 自由 |
| 2 | 日程 | ◯ | `YYYY-MM-DD`、期間は `YYYY-MM-DD〜YYYY-MM-DD`（全角チルダ〜）、未定は `TBA YYYY-MM` |
| 3 | 場所 | ◯ | `都市, 国`（例: `Phu Quoc, Vietnam`／国内は `Tokyo, Japan`） |
| 4 | 公式URL | △ | `https://` から。無ければ空 |
| 5 | 出演者 | △ | `;` 区切り（例: `DJ NOBU;WATA IGARASHI`） |
| 6 | 補足 | △ | ジャンルや一言を `;` 区切り（例: `Techno;House;11日間`） |
| 7 | フェスID | △ | サイトに登録済みのフェスの ID。入れると写真・最新 LINEUP が自動で入りフェス詳細へリンク |

後ろの項目が空なら省略してよい: `[[event|Epizode|2026-12-28〜2027-01-08|Phu Quoc, Vietnam]]`

### 3-2. 開催カレンダー
```
<p>[[calendar]]</p>
<p>[[calendar|2026-12〜2027-02]]</p>   ← 月で絞る（任意）
```
その記事内のイベントカードを月ごとに自動で一覧化する。**イベントカードが1つも無い記事に置くと公開が止まる。** 置くなら本文の最後か最初に1つ。

### 3-3. アーティストカード
```
<p>[[artist-card:dj-nobu]]</p>
<p>[[artist-card:dj-nobu|この夜のクロージングを任された]]</p>   ← 一言（任意）
```
写真・名前・ジャンル・拠点・経歴の冒頭・SNS が自動で入る（データはサイトの ARTISTS から）。
- 一言は**その記事の文脈**（何をしたか、どう鳴ったか）。経歴の言い換えは書かない。
- 1記事に 1〜3 枚。記事の主役級だけ。全出演者を並べない（それはイベントカードの出演者欄）。
- ID はアーティストページの URL の末尾（`/artists/dj-nobu.html` → `dj-nobu`）。

### 3-4. プルクオート
```
<p>[[pullquote|本文の一文をそのまま]]</p>
<p>[[pullquote|本文の一文をそのまま|出典]]</p>   ← 出典（任意。発言者やメディア名）
```
本文の一文を中央に大きく見せる。**本文にある文をそのまま使う**（新しく要約文を作らない）。1記事に 1〜2 本。2文以上を入れない。

### 3-5. 折りたたみ（開閉できる補足）
```
<p>[[details|セットリスト全曲]]</p>
<p>01. Efdemin — Intro</p>
<ul><li>…</li></ul>
<p>[[/details]]</p>
```
見出しを押すと開く補足。中には段落・リスト・他のブロック（イベントカード、プルクオート）を入れてよい。
- 開始 `[[details|見出し]]` と終了 `[[/details]]` は**それぞれ1行の段落**にする。閉じ忘れ・入れ子は公開が止まる。
- 用途: セットリスト、注意事項・持ち物、長い補足、FAQ。本文の流れを止めたくないもの。1記事に 0〜3 個。
- `<details>` タグを直接書かない（必ずショートコードで）。

### 3-6. サイト内リンク
```
[[festival:rural]]  [[artist:dj-nobu]]  [[venue:womb]]  [[article:記事ID]]
[[festival:rural|ラベル]]   ← 表示文字を変えるとき
```
文中に書くと、その詳細ページへのリンクになる（表示名はデータから自動）。アーティスト名は書くだけで自動リンクされるので、`[[artist:…]]` は名前と表記を変えたいときだけ。

### 3-7. インタビュー発言（quote）
```
<p>[[quote|発言本文|話者名]]</p>
<p>[[quote|私にとってDJは、その時々で生まれる一つの作品です|YUTA]]</p>
<p>[[quote|話者名を省いた発言]]</p>   ← 話者名は任意
```
| 位置 | 項目 | 必須 |
|---|---|---|
| 1 | 発言本文 | ◯ |
| 2 | 話者名 | △（省略すると話者の行を出さない） |

- **使いどころ**: インタビューで、地の文に溶かさず本人の言葉として残したい発言。左に細い線が付くだけの軽い見た目で、続けて何本置いても重くならない。本数の制限はない。
- `<blockquote>` は使わない（囲みが重く、並ぶと読みにくい）。
- `[[pullquote]]`（本文の一文を中央に大きく抜き出す。1記事1〜2本）とは別物。発言を大きく見せたいときだけ pullquote。
- **公開が止まる**: 本文が空、項目が3つ以上（半角 `|` が混ざった）。

### 3-8. インタビュー質問（q）
```
<p>[[q|質問文]]</p>
<p>[[q|自身のサウンドを、心象として表すなら何か。]]</p>
<p>回答の段落…</p>
```
- **使いどころ**: インタビューの質問。質問だけをショートコードにし、回答は直後の通常の `<p>` か `[[quote]]` で書く。
- 先頭に赤い「Q」が付き、本文より太く大きい（見出しより小さい）。見出しではないので目次や見出しの装飾には入らない。
- 質問の頭に「——」や「Q.」は書かない（「Q」は自動で付く）。
- **公開が止まる**: 質問文が空、項目が2つ以上（半角 `|` が混ざった）。

### 3-9. 年表（timeline）
```
<p>[[timeline|年;出来事|年;出来事|…]]</p>
<p>[[timeline|2004;東京のクラブでDJデビュー|2009;MATSURI DIGITALに加入|2015;テクノへ移行|2016;Liquid Drop Grooveを設立]]</p>
```
- 項目は `|` で区切り、各項目は**最初の `;`** で「年」と「出来事」に分ける（2つ目以降の `;` は出来事の文字として残る）。
- 年は数字に限らない: `2021.07` `2020〜2021` `1990年代` など。
- 年が左、出来事が右の縦並び。スマホでも横スクロールしない。2〜12項目を想定（上限は強制しない）。
- **使いどころ**: 経歴を語る章の中に1つ。経歴を全部並べず、話の流れに関わる節目だけ。
- **公開が止まる**: 項目が0個、`;` が無い項目、年または出来事が空。

### 3-10. プロフィール（profile）
```
<p>[[profile|名前|項目;値|項目;値|…]]</p>
<p>[[profile|YUTA|拠点;Tokyo|レーベル;Liquid Drop Groove|共同レーベル;Chronoscope（The Gods Planet × LDG）|主催;EDEN / SPECTACLE]]</p>
<p>[[profile|YUTA]]</p>   ← 項目なしも可
```
- 1つ目が名前、以降が `項目;値` の組（最初の `;` で分ける）。項目は0〜8個を想定（上限は強制しない）。
- **使いどころ**: インタビュー記事の冒頭、リードの直後に1記事1個。値は事実だけ（拠点・レーベル・主催パーティなど）。確認できない項目は書かない。
- **公開が止まる**: 名前が空、`;` が無い項目、項目名または値が空。

**3-7〜3-10 の共通ルール**
- 必ず単独の段落 `<p>[[…]]</p>` に書く。文の途中に混ぜると**公開が止まる**（そのまま画面に出るのを防ぐため）。
- 値に半角 `|` `]` を書かない（全角 `｜` `］` は可）。`&` などの記号はそのまま書いてよい。
- 値の中に太字・リンク・他のショートコードは書けない（タグが文字のまま表示される）。
- 日本語本文（BODY）と英語本文（BODY_EN）で同じ書き方。

## 4. 本文の組み立て（量と順序の目安）

| 種別（CATEGORY） | 構成の目安 |
|---|---|
| REPORT | 導入（いつ・どこで・何が、現場の第一印象 2〜3 文）→ `<h2>会場とサウンド</h2>` → `<h2>ハイライト</h2>` → `<h2>クラウドとカルチャー</h2>` → `<h2>総括</h2>` |
| INTERVIEW | リード → `[[profile]]` → 各章（`<h2>` → `[[q]]` → 回答段落 / `[[quote]]`）→ 該当章に `[[timeline]]` → `<h2>INFORMATION</h2>` |
| NEWS | リード 1〜2 文（何が・いつ・どこで）→ 詳細 → `<h4>開催情報</h4><ul>…</ul>` またはイベントカード |
| GUIDE（まとめ） | 見どころ 2〜3 文 → 項目ごとに `<h2>` ＋ イベントカード → 最後に `[[calendar]]` |
| COLUMN | 論点ごとに `<h2>` |

- 本文の長さ: 1,200〜3,000 字（読了 3〜8 分）。
- 見出しの中で語を割らないよう、`<h2>` は 25 字以内を目安に。
- アーティスト名・会場名・フェス名は**公式表記**（大文字小文字を変えない: `Ben UFO`）。

### インタビュー記事（CATEGORY: INTERVIEW）の構成

リード → `[[profile]]` → 各章（`<h2>` → `[[q]]` → 回答の段落 / `[[quote]]`）→ 年表が必要な章に `[[timeline]]` → `<h2>INFORMATION</h2>`。
インタビューの発言は `<blockquote>` ではなく `[[quote]]` を使う。`[[pullquote]]` は1〜2本、`[[profile]]` は1記事1個。質問・quote・timeline・profile はそれぞれ単独の `<p>` にする。

## 5. 文体のルール（要点。詳細はスタイルガイド）

1. **事実主義**: ソースに無いことを書かない。日時・会場・出演者・料金は確認できたものだけ。推測は「〜とみられる」と明示。
2. 煽り・常套句・観光ガイド調を避ける。「必見」「圧巻」「最高」のような評価語より、何がどう鳴ったかの具体。
3. 1文は短く。読点でつなぎすぎない。
4. 締めの一文は、その出来事がシーンにとって持つ意味か、次の予定。
5. 英語版（BODY_EN）は直訳でなく、英語圏の読者が知らない前提（会場の性格、日本のシーンの文脈）を 1 文補う。

CATEGORY: REPORT
DATE: 2026-09-28
AUTHOR_ID: techno-japan
EXCERPT: 中秋の名月に合わせて開かれる野外フェスティバルが、7年目を迎え新潟・糸魚川の池のほとりへ。国内外16組が満月の夜から3日間をつないだ。
TAGS: niigata, outdoor, report
festivalId: otsukimi
artistIds: dj-nobu
IMAGE: 夜のドームステージと観客を正面から（横長）

### BODY
<p>9月25日、満月の夜に幕が開く。御月民 -OTSUKIMI- は、その名の通り中秋の名月に合わせて開かれる野外フェスティバルだ。</p>

<p>…</p>

## 7. チェックリスト（出力前に AI 自身が確認する）

- [ ] ショートコードは全部 `<p>[[…]]</p>` で、値に `|` `]` を含まない
- [ ] `[[quote]]` / `[[q]]` / `[[timeline]]` / `[[profile]]` は単独段落にし、値に半角 `|` `]` を入れない（全角 `｜` は可）
- [ ] `timeline` / `profile` の各項目は最初の `;` で分け、年・出来事／項目名・値を空にしない
- [ ] 使った ID（フェス・アーティスト・会場・記事）は実在する。分からないものはブロックにしていない
- [ ] `[[calendar]]` があるならイベントカードが 1 つ以上ある
- [ ] `[[details|…]]` は必ず `[[/details]]` で閉じ、入れ子にしていない
- [ ] プルクオート 1〜2 本、アーティストカード 1〜3 枚、`<h2>` 3〜6 本
- [ ] `<img>` `<table>` `<details>` `<iframe>` `style=` Markdown を使っていない
- [ ] EXCERPT は 80〜120 字、TAGS は小文字英単語
- [ ] 日付は `YYYY-MM-DD`、期間の区切りは全角「〜」
