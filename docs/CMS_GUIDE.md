# CMS の使い方 — 画面・ボタン・ショートカット・手順（共有用、2026-10-10）

対象: TECHNO JAPAN の CMS（`/cms.html`）を使って記事・フェス・アーティスト・会場を更新する人。
記事本文の中でできることは [writing/ARTICLE_BODY_FEATURES.md](writing/ARTICLE_BODY_FEATURES.md)、文章のルールは
[writing/Techno_Japan_Web_Style_Guide.md](writing/Techno_Japan_Web_Style_Guide.md)。

## 0. まず知っておくこと（3つ）

1. **データの正本はスプレッドシート「LP」**。CMS はそのシートを読み書きする画面。コードにデータは書かない。
2. **「Save」は保存、「🚀 Publish Now」は公開。** 保存しただけではサイトは変わらない。Publish Now を押すと `data.js` が GitHub に push され、数分で本番に出る（＝ Publish は「公開」操作）。
3. **CMS 自体が更新されたら Cmd+Shift+R（強制リロード）。** 古い画面のまま操作すると、直ったはずの不具合が再現する。URL に `?cb=数字` を付けて開くのも有効。

## 1. ログインと画面の構成

| 項目 | 内容 |
|---|---|
| ログイン | 開くとパスワード入力。合っていれば 24 時間有効なトークンが保存され、期限切れは1回だけ自動で取り直す。「🔒 Logout」でトークンを捨てる |
| セクション | 🏠 Home（ダッシュボード）/ VENUES / FESTIVALS / ARTISTS / EVENTS / ARTICLES。各セクションに **List**（一覧・編集）と **New**（新規）のタブ |
| 一覧の操作 | **Refresh**（シートを読み直す）、並べ替え（Name / Date / City …）、**📊 未完成**（入力が足りない行を上に） |
| 共通ツール | 🖼 Images（画像一覧）/ 📊 Stats（件数などの統計）/ 🔍 Find & Replace（横断置換）/ ⚡ Quick（素早く1件追加）/ ⚡ Bulk Assist / ⬆ Bulk Import（まとめて取り込み）/ ⬇ Export data.js |

## 2. キーボード

| キー | 動き |
|---|---|
| ⌘S（Ctrl+S） | 開いているフォームを保存 |
| ⌘K（Ctrl+K） | 検索欄にフォーカス |
| ⌘⇧F（Ctrl+Shift+F） | 記事の集中モード（全画面執筆）を切り替え |
| Esc | メニュー・ダイアログ・集中モードを閉じる |
| Shift+Enter（記事本文） | 段落を分けずに改行 |
| @（記事本文） | その場でフェス／アーティスト／会場を名前検索してリンクを入れる |

## 3. 共通の入力部品

| 部品 | 使い方・注意 |
|---|---|
| 画像 | ファイルを選ぶ／ドラッグ／ペースト。端末側で webp に変換・縮小してから保存。**Image from URL** は取得に失敗すると無変換の原本を保存し、webp でないと Drive 同期で飛ばされる（成功トーストが出ても反映されないことがある）。表示位置は「↖」の9方向ボタン（顔が切れるときは top） |
| 住所 → 座標 | **📍 検索**（住所から座標）／**Geocode**。会場・開催回の地図に使う |
| ID | 小文字と数字とハイフンだけ（`dj-nobu`）。**一度決めた ID は変えない**（URL とリンクが切れる） |
| 翻訳 | **✨ 翻訳**（欄ごと）、記事は **✨ 英語版を一括生成**、**✨ 本文をまるごと英訳** |
| AI 生成 | **AI Generate**（紹介文の下書き）、**✨ AI Excerpt 生成**、**✨ AI タイトル候補**。出力は必ず読んで直す（事実主義） |

## 4. セクション別の手順

### FESTIVALS（フェス）
- フェスは **ブランド（FESTIVAL_ID）** と **開催回（EDITIONS）** の2段。日程・会場・座標・チケット・フライヤー・状態は開催回側に入れる。FESTIVALS の DATE を翌年で上書きして過去回を消さない。
- **「+ 開催回を追加」** で新しい年の回を作る（最大年＋1）。同じ年に2回目があるときは「同じ年にもう1回」（表示は `2026 #2`）。
- **「次回開催を作成」** は会場・住所・座標を引き継ぎ、日程・チケット・フライヤー・LINEUP は空で作る。元の回はそのまま残る。
- LINEUP は **Fetch Lineup (AI)**（公式情報から候補を拾う）→ 確認、または **Bulk Text Input**（名前を貼って **Add Artists**）。ARTIST_ID は ARTISTS の ID と完全一致させる。**🗑 全部クリア**で消せる。
- 海外フェスは **COUNTRY（ISO 2文字）** を必ず入れる。空だと Airtable 側の国が更新されない。
- 一覧は 📋 List / 📅 Calendar の2表示。

### ARTISTS（アーティスト）
- NAME は原文の大文字小文字を変えない（`Ben UFO` を `Ben Ufo` にしない）。日本語名は NAME_JA。
- BIO_JA / BIO_EN、GENRE、PREF / COUNTRY、SNS（INSTAGRAM / SOUNDCLOUD / BANDCAMP / WEBSITE）。ユニットは SCHEMA_TYPE を `music-group`、MEMBER_IDS に構成員の ID。
- ここに入れた内容が、記事内の **アーティストカード**（`[[artist-card:ID]]`）と自動リンクの出どころになる。

### VENUES（会場）
- SUBTYPE は bar のときだけ出る。HOURS / CHARGE / FEATURES（13 種）。座標は 📍 検索で。

### ARTICLES（記事）
- タイトル／カテゴリ／著者（候補が出る）／画像／ステータス（**Draft** は公開されない。**Published** で公開）／タグ／要約（EXCERPT）／本文。
- 本文エディタのボタン: **VISUAL / HTML**、**＠ ID**、**📦 イベントカード**、**❝ プルクオート**、**📅 カレンダーを挿入**、**📄 テンプレ**（イベントレポート / インタビュー / ニュース / 週間まとめ / フェスまとめ / コラム）、**⛶ 集中モード**、**プレビュー**（横に並べる）、**↗ 本番表示**（本番と同じ CSS/JS で別画面）、**📜 履歴**。
- 画像をクリックすると幅（中央・標準 / 左 / 右 / 全幅 / 小さめ）、トリミング（16:10 / 4:3 / 1:1）、拡大・位置、**2枚セット（50:50）** が選べる。
- 🌐 ENGLISH VERSION に英語を入れると `/en/` の英語ページが出る。
- 読了時間は本文から自動計算。要約が空なら本文の冒頭 160 字が検索結果の説明文になる。

### EVENTS
- 単発イベント。📋 List / 📅 Calendar。FESTIVALS と同じ要領で入力。

## 5. 公開（Publish）の手順と、止まる条件

1. 各フォームで **Save**（シートに保存）。
2. **🚀 Publish Now** → 「data.js をビルドして GitHub に直接 push します」の確認 → **差分の要約**（紹介文 11 → 11 のような件数）が出る → 確認して公開。
3. 「🚀 Published!」のあと、数分で本番に反映。Publish 後に詳細ページ（フェス・アーティスト・会場・記事）も自動で作り直される。

**止まる・止めるべき条件**
- 公開中と同じ内容なら送らない（空の公開を「成功」と呼ばない）。
- 差分の要約で件数が急に減っていたら（例: 紹介文 11 → 0）**公開しない**。列が落ちている。
- EDITIONS に同じ EDITION_ID が2行あると Publish は失敗する。
- 存在しない ID をショートコード（`[[artist-card:…]]` のフェスID など）に書いた公開記事があると、生成が止まる。下書き（Draft）なら止まらない。
- 失敗は消えないパネル（赤）で残る。消えるトーストに戻していないので、見逃したら画面を上まで戻す。

## 6. 画像の反映と同期

- 本文・ヒーロー画像は保存時に Google Drive へ上がり、**Sync Drive Images**（自動、定期）でサイトに取り込まれる。webp 以外は同期で飛ばされる。
- 同期の状態は CMS の同期ボタンで見られる。すぐ反映したいときは GitHub Actions の「Sync Drive Images」を手で動かす。

## 7. 困ったとき

| 症状 | まず疑うこと |
|---|---|
| 保存したのにサイトが変わらない | Publish Now を押していない／押したが数分待っていない／ブラウザのキャッシュ（Cmd+Shift+R） |
| CMS の挙動が直っていない | CMS 自体が古い。Cmd+Shift+R、または `?cb=数字` 付きで開き直す |
| Publish が失敗する | 赤いパネルの文言を読む。EDITIONS の重複、参照切れの ID、列落ち（差分要約の件数）が多い |
| 画像が出ない | webp か。Image from URL で失敗していないか。同期がまだか |
| 「Access denied」 | トークン切れ。再ログイン（自動で1回取り直す。だめなら Logout → 開き直す） |
| 一覧に無い | Refresh。別タブで保存した内容はキャッシュに乗っていない |

## 8. やってはいけないこと

- スプレッドシートの **1行目（見出し行）を触らない**。壊すとフェスが全部消えたように見える（過去に発生、復旧済み）。
- ID を後から変えない。日付を上書きして過去回を消さない。
- 動作確認のために本番データに書き込まない。確認は読むだけで行う。
- Publish を「保存」のつもりで押さない。
